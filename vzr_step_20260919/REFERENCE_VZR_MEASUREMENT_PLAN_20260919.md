# vzr 同定のための計測計画（2026-09-17）

目的: OptiTrap モデル F_z = az·sin(vz·Δz)·cos(**vzr**·d_r) の vzr を実機で決める。
vzr は「Δz と d_r が**同時に**立つ」ときにしか力に現れない。1 軸ステップでは
どちらかが常に 0、既存の 3D 連続記録は z 駆動 ≤90 Hz で真の Δz が 0.01–0.04 mm
しかなく（z 共振 289 Hz に粒子が追従してしまう）、どちらも原理的に不可。

> **⚠️ 2026-09-19 追記: このままでは取得側の安全検査を通らない。**
> 滑らかな外部指令が通る `imported` 経路の上限は オフセット 9.5 mm / 速度 800 mm/s / **加速度 100,000 mm/s²** /
> 端点 0.01 mm（ff_heart 実記録の `trajectory_metadata.json` で確認）。下の指令は z 成分（0.15–0.25 mm @187 Hz、
> A·ω² = 206k–344k mm/s²）のせいで全て 206k–352k になり弾かれる。通るのは単軸の `*_only`（x 51k / y 60k）だけ。
> 原理的な制約: |Δz| ≥ 0.1 mm には粒子加速度 k_z·Δz ≈ 330k mm/s² が要るので、100k 以下の滑らかな指令では
> z 共振（290 Hz）に乗せない限り届かない（共振近傍はドループ −13〜22% で脱出側に動くので不可）。
> 取りうる道: (A) 取得 PC でこの計測に限り加速度上限を 400k に上げる（kcheck_z の 1 mm ステップで粒子は既に
> ≈3.3M mm/s² を受けて保持している）、(B) x と z の**同時ステップ**に設計し直して `staircase` 経路（振幅のみ検査）で流す。
> また 9/18 の新鮮時 f0_x は 80–83 Hz（計画時の想定 87 Hz より低い）で、ドループ時は 63 Hz まで下がった。
> x 57 Hz 駆動は f0_x 72 Hz で Δx が 1.7 倍、63 Hz で 3.9 倍になり脱出側 → **10 分以上休ませた直後にだけ撮る**。
> 余裕重視なら ALT（50 Hz）。なお ハート 7 mm・10 Hz の FF は線形域（力最大の ≤41%）なので vzr は FF 精度には効かない。

## 何を計測するか（結論）

**x と z を同時に、それぞれの共振の 0.5–0.75 倍の周波数で、非整数比の周波数で駆動する。**

| 段 | x | z | 物理 d_r | 物理 |Δz| | max v | max a | SE(vzr) 2 s | 8 s 換算 |
|---|---|---|---|---|---|---|---|---|
| L1 | 0.4 mm @ 57 Hz | 0.15 mm @ 187 Hz | 0.32 | 0.12 | 227 mm/s | 212k mm/s² | 7.6% | 4% |
| L2 | 0.5 @ 57 | 0.20 @ 187 | 0.42 | 0.17 | 295 | 282k | 3.4% | 1.8% |
| **L3（推奨）** | **0.6 @ 57** | **0.20 @ 187** | **0.53** | **0.18** | **318** | **285k** | **2.1%** | **1.1%** |
| L4 | 0.6 @ 57 | 0.25 @ 187 | 0.53 | 0.22 | 363 | 352k | 1.6% | 0.8% |
| ALT（余裕重視） | 0.7 @ 50 | 0.20 @ 187 | 0.37 | 0.21 | 321 | 283k | 4.3% | 2.2% |

- 模擬条件: ステップ同定 Θ（ar 0.203, vxr 1.467, az 2.7, vz 1.22, γ 0.040）＋純遅延
  τ=2 ms、cos ランプ 0.5 s、観測ノイズ 0.01 mm、SG 窓 x/y 2.7 ms・z 1.5 ms。
- SE は Θ\* での残差ヤコビアンから。z ステップの 2 通りの Θ（az/vz = 2.32/1.39,
  3.13/1.05）でも L3 の SE(vzr) は 2.0–2.1% で変わらない。
- **x 0.8 mm @57 Hz は模擬で脱出**（Δr が力最大 1.07 mm の飽和域に入り共振増幅で発散）。
  x 0.7 @57 は保持だが d_r 0.68 で余裕が薄い。**L1 から順に上げる**こと。
- 各段の前に単軸で保持確認: `vzr_L1x_x0.4_57Hz_only`, `vzr_L1z_z0.15_187Hz_only`（4 s）。
- 安全制限は plan B と同じ |v| ≤ 400 mm/s, |a| ≤ 400,000 mm/s² に収まる
  （S105 ステップ計画の 100 mm/s・28,000 mm/s² では通らないので緩和が必要）。

## y+z 検証 run（軸対称仮定のチェック、1〜2 本）

OptiTrap は軸対称（水平は d_r 経由のみ）だが、ステップ記録は x と y で
k 12%・V 20% の差を示す。x+z で得た vzr と y+z で得た vzr が一致するかで
軸対称近似の妥当性を判定する（10% 超のずれなら方向依存 → モデル拡張が必要）。
y の共振は 82 Hz（x 87）、V 1.18（x 1.47）→ 力最大 1.34 mm。y は奥行き軸で
ノイズ 3 倍（σ 0.021 mm）なので、その分 SE を悪めに見積もる。

| 段 | y | z | 物理 d_r | 物理 |Δz| | 粒子 y± | max v | max a | SE(vzr) 1.5 s → 8 s |
|---|---|---|---|---|---|---|---|---|
| **Y1（推奨）** | **0.5 mm @ 55 Hz** | 0.20 @ 187 | 0.45 | 0.18 | 0.95 | 291 | 281k | 3.0% → 1.3% |
| Y2 | 0.6 @ 55 | 0.20 @ 187 | 0.56 | 0.19 | 1.16 | 313 | 284k | 2.0% → 0.9% |

- 単軸保持確認: `vzr_Y1y_y0.5_55Hz_only`（4 s）→ Y1 → 余裕があれば Y2。
- 模擬は y のステップ値（ay 0.223, vy 1.176, γ 0.036）で実施。x 用の値より
  柔らかいので x の L3 と同じ 0.6 mm でも d_r 0.56 で保持（x 0.8 は脱出だった）。
- ファイル: `vzr_Y1_y0.5_55Hz_z0.20_187Hz`, `vzr_Y2_y0.6_55Hz_z0.20_187Hz`（各 8 s）、
  図 `vzr_Y1_trajectory.png`。
- x と y を同時に振る run は不要（d_r の情報は増えず脱出余裕だけ減る）。

## なぜこの設計か（模擬で分かったこと）

1. 力モデルは Δ=トラップ−粒子にしか依存しない。**低周波の大振幅は Δ を作らない**
   （x 1.2 mm @15 Hz → 物理 Δr 0.04 mm、ar/vxr の SE 14000%）。
2. 共振に近すぎると Δ が飽和域を越えて脱出、遠すぎると Δ が立たない → 0.5–0.75 f0。
3. x と z の周波数を非整数比（57 と 187）にして Δz と d_r の位相を独立にする。
   cos(vzr·d_r) は sin(vz·Δz) に掛かるので、両者が同期していると分離できない。
4. z 単独（z 0.2 @187 のみ）では SE(vzr) 1690% → **x の同時駆動が必須**。
5. 3 軸目（y 0.5 @53）や両軸チャープ（x 0.7 で 40→70 Hz）は模擬で脱出。
   チャープにするなら x ≤ 0.5 mm・40→55 Hz に抑える（f0 の不確かさ対策として有用）。

## ⚠️ 剛性ドループ対策（必須）

9/16 のステップ記録で、トラップ剛性は**稼働 10 分で x −24% / y −35% / z −13%** 落ち、
休止で回復する（HANDOFF「トラップ剛性は稼働時間で落ちる」）。vzr の推定は 5 パラメータ
（ar, vxr, gam, az, vz）を固定して行うので、その固定値と vzr run が**同じ熱状態**でないと
系統誤差になる。手順:

1. **ウォームアップ**: 計測前に 10 分間トラップを保持したまま待つ（定常状態にする）か、
   逆に毎 run 前に 5 分休止して「冷えた状態」に揃える。どちらかに統一する。
2. **サンドイッチ**: 各 vzr run の**直前と直後**に短いステップ（x S105 相当 6 ジャンプ ＋
   z S105 相当 6 ジャンプ、各 ~15 s）を撮る。前後の k が 5% 以上違えば、その run の
   固定値は前後の平均を使い、差を系統誤差として報告する。
3. **順序**: L1→L2→L3 の単調増加で撮ると時間とドループが交絡する。
   L1, L3, L2, L3, L1 のように**往復**させ、同じ段の反復で剛性が一致するか見る。
4. run 間隔は一定（例 90 s）に揃える。

## 時間軸の扱い（2026-09-18 更新）

- 指令とカメラの時間軸は **+182 ppm** ずれている（全記録で一致）。同定・比較の前に
  指令列の時間軸を (1+182e-6) 倍に伸ばして再サンプルする（`real_vzr_fit.py` は既定で実施）。
- 補正後の純遅延は **τ0 ≈ 0.7–0.9 ms**（従来の 2 ms は蓄積ずれ込みの見かけ）。
  187 Hz で 0.8 ms は位相 54°。τ0 は run ごとに同時推定する。
- 記録の末尾にも LED 同期を入れられれば、比のずれを run ごとに直接測れる。

## 遅れの扱い（旧記述、τ≈2 ms は上記により訂正）

- 指令→実トラップは純遅延 τ≈2 ms（Acoutools_eventcam の同定と一致、run 間 1.9–2.4 ms）。
  **フィードフォワード補償は不要**（OFF で撮る）。同定側でトラップ位置を u(t−τ) とし、
  τ を run ごとに同時推定する（`real_vzr_fit.py` の既定）。
- 187 Hz で τ 2 ms は位相 135°。τ 0.1 ms の誤差が 7° なので事前値固定は不可。
- 記録 8 s 中の最初 0.5 s（ランプ）と末尾は解析から除く。

## 位置合わせ

- ステップと同じ **`spatial_alignment = fixed`**（セッション基準の camera→PAT 変換）で
  比較を作る。per-run Kabsch（fit-run）は閉じた軌道で遅れを回転として吸収する
  （`kabsch_delay_absorption.py`）。今回の軌道は閉じないが、統一しておく。
- 残る定数オフセットは同定側の Δ0（3 成分）で吸収する。

## 解析手順

```bash
# 1) ステップ記録で 5 パラメータを確認（既に済: HANDOFF の表）
# 2) 各 run:
python3 ../real_vzr_fit.py <run>/sindy_dataset_3d/state_control.npz --json <run>_vzr.json
#    出力: vzr, τ, Δ0, SE, R²(x/y/z), 物理 Δ の大きさ, vzr_valid
# 3) 合否: vzr_valid が true（R²_z ≥ 0.5 かつ max|Δz| ≥ 0.1 mm）で、
#    L2–L4 の run 間で vzr が SE の 2 倍以内に一致すること。
# 4) 参考として --free all（6 パラメータ+τ+Δ0）も回し、ステップ値と整合するか見る。
```

負の対照（既存 counter_xyz）: R²_z = −2.4、vzr_valid = false と出る。これが
「z が励起されていない記録では推定不能」の判定基準になる。
